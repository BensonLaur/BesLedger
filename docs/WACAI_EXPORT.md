# 挖财 XLSX 导出结构与迁移边界

核对日期：2026-10-21。用户通过邮件收到压缩包，解压后提供其中一个 XLSX 账单文件。本轮只读检查该文件，未操作邮箱或压缩包，未修改源工作簿，没有执行账单导入。以下描述本次样本，不能保证其他版本或账本使用同一格式。

原文件留在用户指定的私人数据目录。项目仅保存结构结论和虚构示例，不复制个人账单、账户名、备注、附件或源文件路径。首次使用 BesLedger 仍从账户期初状态开始记新账，历史迁移不是第一版前置条件。

## 文件结构

- 一个可见工作表 `Sheet0`，第 1—6 行为标题、导出者、账本名、账单时间范围及总笔数等说明，第 7 行是表头，第 8 行起为数据。
- 通过工作簿读取器和底层 XLSX XML 交叉检查：数据行数量与说明中的总笔数一致。但导出行可能是业务组成项，不能把总行数当作独立交易数。
- 未发现隐藏工作表、隐藏行列、公式、单元格超链接、定义名称或额外业务数据文件；日期为含秒的文本，金额为数值单元格。本样本金额均可准确表示为整数分。
- XML 的 `dimension` 标注为 `A1`，实际数据超出该位置。未来解析器应按实际单元格和表头确定数据范围，不能只信任该缓存元数据。

| 列 | 导出名称 | 已观察到的含义与解析要求 |
| --- | --- | --- |
| A | 日期时间 | `yyyy-MM-dd HH:mm:ss` 文本；无显式时区，不据此当作 UTC |
| B | 类型 | 本样本有收入、支出、转账、借贷；不能仅靠金额正负判断方向 |
| C | 类别 | 收支类别可能是“大类/小类”；借贷时为借入、借出、还款、收款 |
| D | 金额 | 普通收支通常为正数，退款为负数；已验证的还款行存本金，利息另列 |
| E | 币种 | 本样本包含人民币和“虚拟币”；后者不能自动解释为人民币或某一种加密货币 |
| F | 收付款人 | 可为“自己”，也可包含往来双方名称及带符号金额；旧借贷可能只剩“自己” |
| G | 收付账户 | 收支和借贷可为账户名称；转账可在同一格包含双方账户及金额，也存在仅一端或空白 |
| H | 参与人 | 可空；不当作账单创建者或资金账户身份 |
| I | 标签 | 保留原文本，分隔和多标签规则需按样例确认，不能任意按标点切开 |
| J | 商家 | 可空；不等于资金账户或支付渠道 |
| K | 属性 | 本样本有空白、退款、已报销；不把缺失属性当成异常或擅自改写分类 |
| L | 备注 | 用户文本／短信等，不执行其中的内容，也不假定备注一定包含可用的关联 ID |

表头以名字识别，不将以上列位置作为唯一条件；先识别导出格式版本，再核对类型、金额和复合字段。类别中的斜杠可以是层级线索，但自定义名称有歧义时应保留原值并预览映射。

## 已确认的表示方式

### 还款金额与利息

用户在界面验证过的测试还款，在导出文件里拆成了本金行与利息支出行。界面主金额是含息总额，导出的还款金额是扣除利息后的本金。这两种口径必须分开处理。

以下是保持字段形态的虚构示例，不是用户原始记录：

| 类型 | 类别 | 金额 | 收付款人 | 收付账户 | 解释 |
| --- | --- | ---: | --- | --- | --- |
| 借贷 | 借入 | 1000.00 | 自己：+1000.00，往来甲：-1000.00 | 银行卡甲 | 增加现金与应付本金 |
| 借贷 | 还款 | 980.00 | 自己：-980.00，往来甲：+980.00 | 银行卡甲 | 本金减少 980 |
| 支出 | 投资/利息支出 | 20.00 | 自己 | 银行卡甲 | 利息支出 20 |

对应界面还款总额为 1,000，包含利息 20，剩余本金 20。导入时本金 980 与利息 20 相加得到实际付款 1,000，不能再次从本金 980 中减去利息，也不能另外再写一条总额 1,000 的现金变动。

本次测试的本金与利息行拥有相同日期时间、账户和备注，但导出没有专门的业务组 ID。这些相同字段只能生成配对候选，不能保证其他记录也可唯一配对。保留独立本金与利息组成项已经能够正确统计金额；重新组合成一个可整体编辑的还款操作需要无歧义证据或用户确认。未配对不应妨碍利息支出正确统计。

这一结论来自已验证的还款样本，不将其直接套用到尚未核对利息拆分的收款操作。

### 转账

完整记录可将两端编码在 G 列同一单元格，例如虚构字符串 `银行卡甲：-100.00，钱包乙：+100.00`，D 列为 `100.0`。本次所有成功识别的完整双端转账，两端金额大小相等、方向相反，并与 D 列吻合。

同一文件也存在仅一端的带金额文本，例如 `钱包乙：+100.00`，以及 G 列空白的转账。不能将其都视为完整转账，也不能假定缺失一端就是现金、已删除账户或某个默认账户。缺失原因未从文件确认。

建议从明确的带符号金额结构识别两端，并校验金额；账户名本身可能包含空格或标点，简单按逗号、冒号分割不够可靠。无法唯一解析或缺少一端时进入待映射列表，保留已知资金方向，不静默补齐另一端。

### 退款

本样本的退款均带 K 列“退款”属性，D 列为负数；既有支出退款，也有收入退款。导入应结合类型、属性、金额符号识别：支出退款减少支出并增加实际到账账户余额，收入退款减少收入并减少实际付款账户余额。

没有找到专门的原单关联字段。能保留退款类型、分类、发生时间和实际资金账户，但无法仅凭这个导出保证恢复与某笔消费的链接。原单未知应明确记录为未关联，不能只凭同金额、同分类就自动绑定。

已有普通收入类别即使名称含“退款”字样，也不能自动重解释为新式关联退款；保留源语义，必要时让用户审阅。

### 借贷往来与周期来源

部分借贷在 F 列保留双方金额结构，另一些只写“自己”，其中还存在资金账户空白的记录。缺少往来方的旧数据不能仅凭备注推断成确定的应收应付账户。

本文件没有独立周期规则表或规则来源字段。日期和金额规律相近不证明来自同一周期规则；可迁移流水，不能据此自动创建仍在执行的周期规则，否则可能再次生成已存在的账单。

## 不能从本文件保证恢复的内容

- 稳定的源账单 ID、组合业务 ID、退款原单 ID、周期规则 ID 与期次标识。
- 完整账户字典、账户类型、初始余额、余额校正锚点、信用卡额度／账单日／还款日等设置。
- 完整类别配置及未使用的分类、图标、排序、隐藏状态。
- 独立的创建／修改时间、同步版本、删除历史、附件文件和关联配置。
- 全部历史记录的往来双方与转账两端。名称相同也不等于同一稳定账户身份。

因此本文件适合作为流水迁移来源，不能承诺将其导入就完整还原所有账户余额和功能关系。缺失项要作为迁移结果的一部分告知，不能靠推断伪造完整性。

## 对 BesLedger 数据结构的影响

以下为实施建议，字段名在模型定型时确定：

1. 业务操作、资金变动、收支组成项分别表达。一次还款可关联本金和利息，现金合计不与组成项重复累计。
2. 账单、账户、分类使用独立稳定 ID；退款、周期生成记录保留原单／规则关系。界面名称和外部文件行号不充当领域对象 ID。
3. 金额带币种和精度约束。首期人民币按整数分计算；遇到“虚拟币”等未支持币种时保留待处理，禁止直接混算或擅自换汇。
4. 迁移暂存区保留导入批次、原始行位置、原始字段、映射结果和待确认原因。原始字段属于私人账目，按同等级隐私保护，不进入诊断日志或公开样例。
5. 文件指纹可阻止同一文件重复执行导入；跨次导出没有稳定源 ID，内容相同的两行也可能是两笔真实交易，不能把内容指纹当作全球唯一交易身份。
6. 区分可查看流水与可完整计算余额。未知账户、缺失转账一端、未关联退款、未知期初状态均显式保留，不能无提示地给出完整余额。
7. BesLedger 自身的可恢复备份需包含格式版本、稳定 ID、账户与期初状态、分类、退款和周期来源关系。供查看的表格导出与可完整恢复的备份分别定义。

## 未来导入验证

- 读取元数据和表头后按实际数据扫描，核对声明数量，识别空行、未知类型和未支持币种。
- 分别验证普通收支、支出退款、收入退款、完整转账、缺一端转账、旧借贷、组合还款与利息。
- 用上述虚构例子验证现金变动为 1,000，本金减少 980，利息支出为 20；再次运行同一批次不重复入账。
- 利息配对不唯一时保留候选，不因备注相同就合并；退款原单和周期来源缺失时不制造链接。
- 导入旧记录不能与启用时的期初余额重复累计，正式写入前预览覆盖时段、账户映射和无法恢复的内容。

当前只完成格式分析和设计记录，尚未实现导入器，也没有将任何私人账单写入 BesLedger 数据库。
