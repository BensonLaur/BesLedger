更新：2026-10-23。身份、四种主状态、发现下载、显式首次上传、冲突与删除协议均已实现。设备同步密钥保存见 SECURITY_AND_RECOVERY.md，实际验证和设备边界见 DELIVERY_VERIFICATION.md。

## 交付要求

真实 GitHub 登录、独立私有数据仓库创建/选择、远端已有账本发现与下载已纳入完整第一版。开发者 gh 已登录只用于开发操作，不等于最终用户已经在应用内登录。后续按 DELIVERY_SCOPE.md 验收，不能以演示状态或 PAT 表单替代。

## 账本身份与发现

账本在本地首次创建时就生成永久 `ledgerId`。改名、绑定 GitHub、下载到新设备不改变它。同名但 ID 不同的账本独立存在；GitHub 登录不触发合并。

列表来自本地账本与确认过的专用私有存储，按 `ledgerId` 合并显示。一个仓库可容纳多本账，每本对应 besledger/v1/<ledgerId>.json；名称、账户和流水均在客户端加密，未解密前只显示账本随机 ID 的简短标识。

“显示 GitHub 下的账本”指授权存储范围内的 BesLedger 账本，不扫描或要求访问用户所有私有项目。目录名称等信息若加密，新设备应先解锁或显示待解锁占位，不能依赖读取全部交易才能列出账本。

## 四种主状态

这些状态相对于当前设备，以及最近一次成功确认的云端信息计算。

| 主状态 | 含义 | 常见动作 |
| --- | --- | --- |
| 仅本地 | 本机有完整账本，云端尚无已确认的对应副本 | 本地使用，或启用同步 |
| 已同步 | 本地与最近确认的云端账本版本一致，没有待上传变更或未解决冲突 | 查看、编辑、检查更新 |
| 待同步 | 两边存在对应账本，有待上传、待下载或待合并的变更 | 同步，必要时处理冲突 |
| 仅云端 | 已发现云端账本，本机尚无完整可用副本 | 下载到本机 |

状态由底层事实推导，不依赖手动维护一个容易失真的四值枚举。每个账本应记录本地可用性、云端绑定、已确认的账本版本、待同步操作和最后检查时间。

## 任务和问题提示

- 启用了同步但第一次上传尚未成功：显示“仅本地 · 等待首次上传/正在建立同步”。同步意图与云端副本是否存在分开保存。
- 上传或下载中：在主状态上附加进度，不提前宣布同步完成。
- 断网：显示最后同步或检查时间；已知旧版本一致不代表当前云端一定没有新修改。
- 授权过期、权限变化或远端不可访问：保留绑定和本地记录，提示重新连接或检查。不直接推断云端已被删除。
- 同记录并发修改、删除与修改冲突：显示“待同步 · 有冲突”，保留双方版本，避免静默覆盖。
- 本地已有密文但尚未解锁：附加解锁状态。下载、解密与建立可编辑本地副本分别处理。

## 创建、下载与修改

没有连接 GitHub 时，创建本地账本即可开始使用。登录只准备存储并发现云端目录，不上传本地账本，也不自动下载云端内容。用户点击具体账本的“首次上传”才建立远端副本；失败后保留本地记录重试，不重复创建新账本。后续修改需点击“同步”，当前不承诺后台实时自动上传。

下载使用明确的云端版本，暂存并校验成功后再建立正式本地副本。期间云端变化则继续拉取更新；中断下载不会留下可编辑的半份账本。

每次本地修改与待同步操作原子保存。操作具有唯一 ID，远端成功但响应丢失时，重试可以识别已经完成的操作。不同记录的独立修改可自动整合，同一记录的并发修改根据共同版本检查并交给用户处理。

云端使用 Contents API 的 SHA 比较写入，每本账的完整加密快照包含其流水和引用账户定义，一次提交完成，不拆成可能半更新的多个业务文件。Git 的原子提交能力不替代应用的财务约束和冲突处理。

一个仓库容纳多本账时，需要检查当前账本的版本/内容，而不是把任何仓库提交都当成所有账本发生变化。

## 删除、解绑和账户切换

- 移除本机副本：已经确认云端完整且无待上传变更时，可转成仅云端；未上传内容先处理。
- 删除云端账本：属于独立的明确操作，要考虑删除标记，避免旧设备上线后把已删除账本重新上传。
- 退出 GitHub：暂停授权访问，保留本地账目和已有绑定信息。
- 切换 GitHub 账号：重新校验授权范围，不自动把原账号绑定的数据上传到新账号。
- 将两个不同 ID 的账本合并：是独立的数据导入操作，须预览和确认，不属于普通同步。

## 跨账本共用资金账户

用户已确认多个账本共用同一资金账户和余额。账户拥有独立于账本的稳定身份；账单属于某个账本，但引用共用账户。GitHub 登录账号与这里的资金账户是两种不同概念。

账户余额由期初状态与有效资金变动计算，转账两端及借贷本金／利息一起生效。每本账只同步引用的账户定义，不同步整个设备的余额投影；不能因为某本账已同步，就宣称账户在所有设备上的总余额都完整。

仅本地账本和仅云端账本并存时，完整余额可能需要当前设备没有的流水。当前展示“本机已知范围”，不下载的云端流水不会被当成完整账目。保持以下约束：

- 不把未下载账本当作零，不把局部流水计算结果无提示地展示为完整余额。
- 不因启用另一本账的同步而上传仅本地账本的交易或可还原这些交易的账户明细。
- 账户余额投影与其对应版本、范围一起保存，避免用旧余额叠加已计入的新流水。
- 账户同名不自动合并；恢复、导入与多设备新建时需要识别账户身份冲突。
- 不因删除一本账就删除仍被其他账本引用的共用账户；删除对余额的影响需明确预览。

四种账本主状态不替代账户余额完整性提示。

## 本地已有账本后开启 GitHub 同步

资金账户（例如测试现金）、账本和 GitHub 登录账号是三种独立身份。已有本地账本不需要为登录 GitHub 重新创建；首次上传只为原 ledgerId 增加 GitHub 数字用户 ID、仓库所有者与仓库名绑定，不改账本或资金账户身份。

| 登录前情况 | 登录并发现后的显示 | 用户选择后的行为 |
| --- | --- | --- |
| 手机有本地账本 A，云端为空 | A 仍为仅本地 | 点击 A 的首次上传，产生同一 ID 的加密云端副本 |
| 手机有 A，另一台 BesLedger 已上传 B | A 为仅本地，B 为仅云端 | 可独立上传 A、下载 B，也可继续让 A 仅本地 |
| A 与 B 名称相同但分别创建 | 仍是两个独立 ID | 不按名称合并，下载后可以自行改名区分 |
| 本机已有同一 ID 的云端账本副本 | 对应同一本账 | 同步时合并独立修改，同笔冲突要求显式选择，不整库覆盖 |

这里的“其他平台”是 BesLedger 的 Web/PWA、Android 或其他设备。其他记账软件的数据库、表格或任意 GitHub 文件不属于自动发现范围。

可按以下顺序验收，使用虚构测试账即可：

1. 在原手机导出完整加密备份并通过系统分享保存到应用外的位置，独立保存恢复密钥；不要先卸载或清空数据。
2. 直接覆盖安装同签名新版，解锁后确认原账户、流水和账本仍存在。若签名冲突，保留旧应用；确认外部备份可用后再安排迁移。
3. 先在另一台设备创建并上传不同的虚构账本 B，再在原手机登录同一 GitHub 账号。
4. 确认手机 A 仍为仅本地且原账目未改，B 显示为仅云端。只登录不应让 A 自动上传。
5. 点击 A 的首次上传，随后在另一端解密下载 A；验证稳定账本身份和原流水保留。
6. 手机用 B 原设备的恢复密钥下载 B，确认 A、B 并列而非覆盖。0.1.1 验证后记住每本账各自的同步密钥，下次解锁后自动使用。

## 当前工程边界

1. 使用完整账本快照与 Git 历史，尚无增量分块或历史压缩；单本密文上限 25 MB。
2. 本地空间和新增设备同步密钥加密保存，跨新设备仍需原始恢复密钥。
3. SHA 比较写入、重复重试、实体版本向量与墓碑负责并发及删除收敛，不按最后写入者静默覆盖。
4. 两本不同 ID 账本的人工合并尚无入口；同名资金账户也不会自动合并。

测试应覆盖首次上传失败、部分下载、请求成功但响应丢失、两端修改、离线恢复、令牌失效和删除后的旧设备上线。
