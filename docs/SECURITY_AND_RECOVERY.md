# 加密、授权与恢复边界

实施决定：2026-10-21。这里描述已实现格式及操作约束，真实设备和生产授权验收结果另见 IMPLEMENTATION_STATUS.md。

## 本地空间

Web 使用 Dexie/IndexedDB；Android 使用独立 SQLite 原生适配。两者只落盘完整加密空间、密钥封装头、递增存储版本与上一版密文。账本名称、账户、金额、备注、搜索索引不在落盘明文中。解锁后在内存构建查询和余额投影，适用于个人规模账本。

随机 256 位主密钥用于 AES-256-GCM；每次使用独立随机 96 位 nonce，并认证格式版本及用途。解锁口令以 PBKDF2-SHA-256、随机 128 位 salt、600,000 次迭代派生封装密钥。独立的 64 位十六进制恢复密钥表示主密钥。口令和恢复密钥不一起明文保存在数据库。密钥仅在解锁后的内存中，锁定会清除可控原始字节；JavaScript 垃圾回收不能保证所有历史内存副本立即归零。

这能保护复制到其他位置的数据库文件，不能保护已解锁设备、浏览器扩展、恶意脚本、系统管理员或被控制的系统。本机首次创建仍须输入至少 10 字符口令；恢复密钥必须独立保存。浏览器清理站点数据仍可删除密文，不把加密当作备份。

写入先校验完整业务，再加密，最后进行短事务版本比较。失败保留原版与草稿；多个窗口不允许旧版本静默覆盖。每次保留上一版密文，数据库结构升级不采用删库重建。

## 备份与恢复

“我的 → 导出完整加密备份”生成 `.besledger` 文件，包含格式版本、密钥封装和加密数据。保留稳定实体身份、账户期初、退款关联、周期期次、版本向量和删除标记，不包含 GitHub token。

恢复前校验文件大小、格式版本、GCM 完整性、日期/整数金额、引用及业务约束，再显示内容数量。用户确认后替换当前空间并保留上一版本。恢复可使用原口令或恢复密钥，设定新口令，重新生成设备身份，保留实体因果版本。未知未来 schema 拒绝恢复；v1 到 v2 的迁移保留身份与数据。

恢复旧备份不等于撤销云端删除。已同步的删除标记不会被旧快照自动复活。使用“我的 → 回收站”显式恢复，形成继承墓碑的新版本，再同步。先恢复账本、原支出，再恢复相关退款；不自动恢复之前已主动删除的其他流水。

## 同步格式与数据范围

数据仓库必须属于已登录用户且私有，并在每次访问前读回核对。云端文件为 `besledger/v1/<ledgerId>.json`，只暴露随机账本 ID、文件大小、Git 提交时间和密文；账本/账户名称及业务信息均加密。每本账以一个原子文件版本发布，Contents API 的 SHA 比较防止写入覆盖。应用内修改先落盘，主动同步时合并批次并写快照，不把每次键盘编辑上传。

当前采用完整账本快照，尚未实现不可变增量块/历史压缩；Git 历史会增长。单本密文读取上限 25 MB，完整本机备份校验上限 50 MB；达到上限会明确失败，不截断数据。历史密文保留在 Git 中，删除远端当前版本不构成历史擦除。

每个实体使用设备版本向量。独立记录可合并，同笔修改、删除与编辑并发保留双方。合并后再次校验退款等跨记录约束；不满足约束时阻止发布。上传成功但响应丢失，重试根据语义版本识别已完成结果。周期期次使用稳定 ID，墓碑阻止重新补生成。

只上传当前账本及被其引用的共用账户定义，不上传其他仅本地账本的流水或由它们推导的余额。账户余额始终标注“本机已知范围”，不把未下载账本、其他设备本地账当作零。账户期初属于用户明确选择同步的账户定义；首次同步确认时应核对它属于该共用资金账户。

## GitHub 授权与密钥隔离

选择 OAuth App 的 Device Flow：Web 和 Android 使用同一公开 client ID，用户在 GitHub 官方页面输入一次性授权码，最小服务只转发固定的设备码与 token 端点。无需 client secret，避免静态页面/APK 泄露秘密，也不依赖本机授权代理。服务不接收业务数据或恢复密钥，不落盘 token，不记录响应体；来源白名单、请求长度及短时限流在服务端校验。

创建私有仓库需要 OAuth `repo` scope；该 scope 比单仓库权限更广，登录界面明确提示。实际客户端仅操作用户选择且读回确认为其所有的私有仓库。未请求删除仓库、组织管理等 scope。GitHub App 的细粒度安装及新仓库选择有额外流程，本版采用官方文档明确支持的 OAuth 创建仓库路径，不能宣称 token 自身只具备单仓库权限。

token 只在内存，刷新、锁定或退出后需重新授权；GitHub 会记住用户对应用的既有授权。退出当前设备不撤销 GitHub 服务端授权，界面提供官方撤销入口。重新连接先核对 GitHub 数字用户 ID，不把旧绑定自动迁移到另一个账号。

首次上传默认使用当前空间恢复密钥作为云端解密凭据。另一设备可以有独立本地口令/主密钥，同步时输入原设备恢复密钥；它只在当前账本管理页面内存保留，不发送到授权服务。请明确保管原始同步恢复密钥，不能用新设备新建空间的恢复密钥替代。

官方依据：[OAuth 授权](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps)、[创建用户仓库](https://docs.github.com/en/rest/repos/repos#create-a-repository-for-the-authenticated-user)、[Contents API](https://docs.github.com/en/rest/repos/contents#create-or-update-file-contents)。

## Android 签名与工具

本机专用签名保存在 `private/signing/`，Windows ACL 仅允许当前用户与 SYSTEM；JKS 口令使用当前 Windows 用户 DPAPI 加密存入 `credential.clixml`。临时口令文件在 `finally` 中删除。签名由 RSA-3072、SHA256withRSA 生成，别名 `besledger-release`，有效期 10,000 天。公开证书可以发布，私钥、口令及 DPAPI 文件禁止提交。

后续升级必须复用同一签名，不覆盖现有密钥。请将 JKS 和实际口令分别备份到个人安全介质/密码管理器；仅复制 DPAPI 文件到另一台电脑通常无法解密。实际口令的受控备份由维护者在本机完成，不粘贴到聊天中。

使用 PowerShell 7 运行项目构建脚本，独立 JDK 21 和 SDK 路径作为参数传入。环境变量只在当前进程临时设置并恢复；不改变系统 Java、SDK 或其他项目。Android 禁止系统自动备份，使用应用内显式加密备份。
