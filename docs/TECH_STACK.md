# 技术栈决策

日期：2026-10-21。状态：作为首轮实施的技术基线记录；尚未创建应用脚手架、安装依赖或完成实机验证。具体版本在搭建脚手架时锁定。

## 需求与约束

- 先满足个人使用，优先打通粘贴银行短信后的四项信息识别。
- 覆盖 iPad、Android 和电脑网页，尽量共用代码。
- 备注粘贴是通用入口；Android 原生短信读取作为条件性增强，不能假设 PWA 可读取短信箱。
- 本地优先、可离线记账，可选择连接 GitHub 私有仓库同步。
- 数据由用户控制，源码发布与账本数据存储分开。
- 以小步实现和验证推进，具体业务功能继续逐项确认。

## 选型

| 层次 | 初步选择 | 职责与取舍 |
| --- | --- | --- |
| 语言 | TypeScript，严格模式 | 统一业务模型、解析结果、存储与同步接口 |
| UI | Vue 3、Vue Router、响应式 CSS | 一套界面适配三种设备；移动输入体验优先 |
| 构建 | Vite、npm | 开发预览与静态打包；实际安装后提交 lockfile |
| 界面状态 | Pinia，按需引入 | 当前账本、编辑草稿和任务显示；持久数据由存储层负责 |
| 本地数据库 | IndexedDB、Dexie.js | 事务、索引、数据版本升级与待同步队列 |
| 离线资源 | vite-plugin-pwa、Workbox | 缓存应用资源、主屏幕入口与更新流程 |
| GitHub 访问 | Octokit、GitHub REST API | 账本目录、版本读取及加密内容上传 |
| 加密 | Web Crypto API、AES-GCM | 认证加密与完整性校验，使用独立账本密钥 |
| 数据校验 | Zod | 检查解析结果、导入和同步格式；与 schemaVersion 配合 |
| 验证 | Vitest、Playwright、真实设备 | 金额、解析、同步状态和浏览器交互验证 |
| 静态托管 | GitHub Pages，发布时配置 | 只发布应用静态资源；个人账目另存专用私有仓库 |

采用 Vue/TypeScript 是当前项目的工程选择，并不要求把既有 C++ 经验迁移成 C++ 前端。首期工作重点是数据正确性、交互和多端兼容，尚无需要额外原生计算模块的性能证据。

Flutter 同样能实现应用型网页与移动端；本项目先围绕浏览器和 PWA 验证，因此选择 Web 技术栈。用户已将 Android APK 纳入本轮必需交付，采用 Capacitor 8 复用界面与 TypeScript 核心。Web 使用 Dexie，Android 优先采用原生 SQLite 适配；具体驱动与加密能力由构建和恢复测试确认。该适配涉及存储、生命周期和迁移，不能视为零成本打包。

## Web 与 Android 版本基线

2026-10-21 核对另一会话的候选版本及官方要求。以下是首轮工程基线，不是已验证的兼容承诺；具体补丁版本在安装和构建通过后锁定，可在保持支持范围的前提下调整。

| 层面 | 初始基线 | 说明 |
| --- | --- | --- |
| Android 最低安装系统 | Android 10 / minSdk 29 | 产品兼容下限；Capacitor 8 技术下限 API 24 不等于本项目承诺 |
| 编译 / 目标 API | compileSdk 36 / targetSdk 36 | 与 Capacitor 8 配套，不表示用户必须安装 Android 16 |
| Android WebView | Chromium 111+ 为初始兼容目标 | 实际内核独立检测；Android 10 不保证自带该版本，日常应更新至可用稳定版 |
| Web 浏览器 | Chrome/Edge 111+、Firefox 114+、Safari/iPadOS 16.4+ | 明确配置构建目标，并检查实际 CSS/API 和持久化行为 |
| Node | Node 24 LTS | 当前本机 Node 24.15.0 满足大版本要求 |
| 原生桥 | Capacitor 8.x | core、cli、android 选择配套稳定版本 |
| Java | JDK 21 | 现有 PATH 的 JRE 8 不足以编译；安装独立 JDK，不破坏其他项目环境 |
| Android IDE | 使用时至少 Android Studio 2025.2.1 | 自动构建也可使用 JDK、SDK 命令行工具与 Gradle Wrapper |
| Gradle / AGP | 跟随锁定的 Capacitor 模板 | 8.0 官方升级基线为 Gradle 8.14.3 / AGP 8.13.0；不各自升级到不匹配版本 |

Android 8/9 的 Chrome 已停在 138，Chrome 139 起要求 Android 10，因此首轮不扩展到 API 24。最低安装系统、WebView 内核与 targetSdk 是三个不同约束。

原型使用 light-dark()，其颜色用法需要 Chrome 123、Firefox 120、Safari 17.5 等较新版本。正式主题应改为 CSS 变量、主题选择器和 prefers-color-scheme，保留已确认配色。Vite 的 build.target 主要解决 JS 语法转换，不自动补齐所有 CSS 和 Web API。还需检查 color-mix、容器单位、inert、剪贴板、Web Crypto、IndexedDB、文件导入导出与 Service Worker。

截至本次准备，标准目录和 PATH 中未发现已配置的 Android SDK、adb、sdkmanager 或 Gradle，尚未构建 APK。搭建后分别记录构建环境、自动化测试内核与真实设备，不将桌面模拟当作真机结论。Google Play 目前对普通新应用/更新要求 API 36；本次 APK 本地安装与以后上架的权限审核分开处理。

依据：[Capacitor 8](https://capacitorjs.com/docs/updating/8-0)、[Java 配置](https://github.com/ionic-team/capacitor/blob/8.0.0/android/capacitor/build.gradle)、[Vite 兼容性](https://vite.dev/guide/build)、[Chromium 系统支持](https://groups.google.com/a/chromium.org/g/chromium-dev/c/vEZz0721rUY)、[MDN 兼容数据](https://github.com/mdn/browser-compat-data/blob/main/css/types/color.json)、[Google Play 目标 API](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en)。

## 当前预览与多端界面的关系

当前会话内预览是用于确认交互的 HTML／CSS／JavaScript 原型，含示例状态，并依赖预览宿主提供的图标与设计控制能力。它不是已经完成的 Vue 应用，也不会原样作为正式安装包交付。

实施时将已确认的页面结构、配色、样式和交互迁移到 Vue 组件，把分类清单作为初始数据，把排序等纯逻辑迁移为可测试的 TypeScript 模块，并用真实存储和业务服务替换模拟状态。原型阶段的成果可以保留，但需要工程化整理与实机验证。

工程化后的同一套 Vue 界面和业务核心用于电脑网页、iPad PWA 与 Android PWA；布局根据屏幕适配。若采用 Capacitor 打包原生安装入口，继续复用 Web 界面，短信权限、系统通知、安全存储等设备能力通过独立的平台适配层接入，不为每个平台重写整套页面。

## 模块边界

计划在应用阶段采用以下职责划分；这些目录尚未创建，也不代表功能已经实现。

```text
src/
  app/                  Vue 界面、路由与应用状态
  domain/               账本身份、金额、账单和确认规则
  recognition/          短信规范化、银行模板、账户匹配、分类规则
  inputs/               备注粘贴与可选原生短信来源适配
  storage/              存储接口与 Dexie 适配
  sync/                 变更队列、同步进度、冲突与恢复
  crypto/               密钥、加解密和格式版本
  providers/github/     GitHub 授权连接及数据访问
```

业务和解析模块可独立测试，不直接依赖 Vue、DOM 或 GitHub。同步模块通过接口访问存储与云端，便于以后替换存储提供方。网络调用和加密准备不放进长时间打开的 IndexedDB 事务；准备完成后，用短事务原子保存账目修改与待同步操作。

## 数据正确性

- 人民币金额以整数分表示，从输入字符串准确转换，检查安全整数范围；不使用二进制浮点元直接累计。
- 交易类型与金额方向独立表达，退款不能只因出现“收入”二字就归为普通收入。
- 转账及借贷本金不计普通收支。基础借贷复用账户资金变动，利息单独形成收入／支出；本金和利息以稳定业务操作 ID 关联，保存、修改、删除及跨端合并保持一致，不能合并出半笔有效操作。
- 关联退款保留原单 ID，每笔退款单独记录金额、发生时间和实际入账账户；累计退款与净支出由关联记录计算，不直接减写原单金额。
- 周期规则与已生成账单分开存储；生成账单保留来源规则 ID、稳定期次标识和生成时字段。修改规则影响后续入账，历史单笔修正不回写规则。历史批量重算已降为后续候选，见 `REFUNDS_AND_RECURRING.md`。
- 保留原文日期片段、补全年份的依据、时区和用户确认结果。首个国内场景默认 Asia/Shanghai，不把粘贴时间当作交易时间。
- 账本、交易与同步操作使用独立 UUID；交易保留版本信息和删除标记。
- 上传使用加密变更批次和适度的完整快照，不将每一次编辑都变成全库密文上传。
- 先做版本检查和明确的冲突处理；不依赖 Git 文本合并理解财务记录。
- 资金账户跨账本共享已确认。账户身份与账本分开，不将同一账户余额复制到每本账后累加。共用账户投影、数据完整性和同步边界见 [同步模型](SYNC_MODEL.md)。
- 账户类别与余额方向分开：信用卡和应收应付可共用计算基础，但提供不同字段和选择范围；信用卡欠款、溢缴款、已出账金额与可用额度不混用。
- 报表聚合使用独立业务模块，汇总、图表与明细复用同一筛选口径，净负数不强塞入占比图；图表库在交互原型确定后再选。
- 迁移适配先写入暂存区并保留来源批次和行位置，处理未知账户、未支持币种和关联缺失；来源行号与内容指纹不替代领域 UUID。实测的挖财还款导出行已经扣除了利息，不能直接套用界面含息总额的解析规则，见 [导出结构](WACAI_EXPORT.md)。
- 可恢复备份需要版本、ID、账户期初和业务关联关系；普通明细表导出不能自动当作完整恢复格式。首期人民币规则保持不变，外部导入的非人民币值不静默换算或混算。

## PWA 的实际边界

PWA 不提供通用短信箱访问。WebOTP 的验证码能力不能用于读取银行交易历史。Android 增强可评估 Capacitor 与 Kotlin 原生插件，独立验证 READ_SMS 的系统限制、安装渠道和用户授权；业务解析器继续共用。平台与政策依据见 [短信访问边界](SMS_ACCESS.md)。

IndexedDB 持久化仍受浏览器配额、回收及用户清理行为影响。申请持久存储、识别配额错误，并在早期提供导出与恢复。浏览器普通标签页和已安装的主屏幕应用可能使用不同存储环境，验收时分别验证，不假设二者自动共享本地账本。

首次访问仍需要加载应用；离线能力须在必要资源成功缓存后才可用。Service Worker 管理应用资源，不替代业务数据同步。以打开应用、切回前台、恢复网络和用户主动触发为基础同步时机，不承诺关闭应用后持续后台同步。

周期账可先在打开应用时按计划日期补齐到期记录，并以稳定期次标识去重。修改规则前如何处理已经到期但尚未生成的期次，需要在实现时明确；不能把新金额悄悄用于全部旧期次。若未来要求应用关闭期间也由云端准时生成，则单独评估执行服务。

基础借贷的约定日期可先在应用内形成到期列表。后台准时提醒、系统通知权限和原生调度属于独立能力，不因保存了还款日就承诺能在关闭 PWA 后准时推送。

如果长期完全本地保存成为强要求，提前评估 Capacitor 与原生 SQLite，并保留导出备份。iPad 原生构建与签名需要相应的 Xcode 环境；当前 Windows 环境可以先完成 PWA 开发和三端访问验证。

## 加密与认证

Dexie 不自动提供加密。云端内容在上传前通过加密模块处理；本地敏感数据的落盘、索引与解锁策略须在持久化实现前明确，不能仅因云端已加密就宣称本地数据库同样已加密。

账本密钥由客户端生成；AES-GCM 每次加密必须正确生成且不复用同一密钥下的 nonce。密文格式包含版本、必要参数与认证信息。恢复密钥应独立备份；如果支持用户口令解锁，使用经过审查的密钥派生与密钥封装方案，不能直接把口令当密钥。

GitHub 访问凭证与账本解密密钥分离。本地功能不要求 GitHub 账号，授权失效不应锁死本地账目。

- 个人验证阶段：细粒度 PAT，限定专用数据仓库及必要读写权限，由用户在各端配置；不写入代码、日志或 Git 历史。
- GitHub 登录属于本轮必需交付：实现真实的 GitHub OAuth/GitHub App 授权流程，核对浏览器跨域、回调、令牌生命周期与私有仓库创建权限，按需使用最小授权服务；授权服务不接收账目明文或解密密钥。PAT 仅作高级备用入口，不能替代登录验收。
- 应用注册、回调配置和必要服务部署需要实际完成；无生产配置的按钮、仅本机代理或开发者 gh 登录不构成应用内登录完成。静态前端和 APK 不嵌入 OAuth client secret 或开发者凭证。
- 纯静态 PAT 方案和辅助授权服务方案分别记录运维边界；不提前引入完整用户账号系统。

## 依赖与验证

脚手架搭建时选择受当前 Vite 支持的 Node.js LTS，记录实际版本并生成 package-lock.json。依赖按功能落地引入，不在文档阶段安装整套库。

优先验证短信金额/余额区分、缺年与跨年处理、分类不确定性、本地重启恢复、同步重试去重、双设备冲突和数据格式升级。Playwright 的 WebKit 用于自动化兼容检查，真实 iPad Safari/PWA 与 Android 浏览器仍需实测。
