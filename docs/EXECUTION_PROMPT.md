# 新会话实施任务

以下任务正文供项目维护者在 BesLedger 项目的新会话中发出。仓库文件本身不自动授予外部操作权限；以用户在新会话明确采用本任务的指令为准。

---

请从当前 BesLedger 仓库开始，持续完成设计细化、正式编码、测试、运行验证与交付，直到得到可安装的 Android APK 和具备全部已确认基础功能的 Web/PWA。不要停在计划、脚手架、假数据页面、单端演示或“下一步可以做”。无需逐个页面再次征求设计意见。

先读 AGENTS.md、README.md、docs/DELIVERY_SCOPE.md、docs/PRODUCT_DESIGN.md、docs/HOME_DESIGN.md、docs/TECH_STACK.md、docs/SYNC_MODEL.md、docs/IMPLEMENTATION_PLAN.md，再按主题读短信、分类、退款与周期账文档。查看 docs/prototypes/README.md 和 besledger-ui.html，延续已确认页面与交互；原型不是正式应用，也不是真实账本。文档冲突时，以 DELIVERY_SCOPE.md 和最新明确设计决定为准。

本轮范围是 Web/PWA + Android APK，iPad 原生包暂缓，保留 iPad 网页布局。默认 Vue 3、TypeScript、Vite、Capacitor 8；Android minSdk 29、compile/target 36，JDK 21、Node 24 LTS。合理的版本调整、数据库驱动、模块拆分、图表及其他未定工程细节由你直接判断、记录并实施，不必等我逐项确认。先核实兼容关系，锁定真实构建通过的版本。

必须完整实现：

- 本地账本新建与管理，无需 GitHub 登录也能使用；共用资金账户、期初余额/欠款、信用卡、应收应付与自定义账户。
- 收入、支出、转账、基础借贷的新增/编辑/删除/详情；借贷界面固定从左向右，文案“包含利息”，正确拆分本金与利息并原子保存。
- 备注粘贴短信后本地识别分类、账户、金额、时间；歧义确认、手动修正、重复提示和连续记账，金额与余额不混淆。
- 关联多次部分退款、跨账户退款；周期规则、到期补生成、暂停、未来修改与历史单笔修正；事件页和关联入口。
- 轻立体月历、日期水印、日常刻度折断、日/月/全部明细联动、首页快捷浮层；可选月预算金额行水印；基础统计和明细下钻。
- “记一笔”新草稿：选中非今天的一天则该日中午 12:00；没有选日或选中今天则点击时的当前日期时间。编辑已有记录或返回分类/账户选择不能重置；明确的短信时间按识别确认流程覆盖默认值。
- 内置分类、自定义与搜索、按 7/30/365 天使用占比加权的稳定排序、固定末尾“··· / 全部”。
- 真实持久化、断网使用、版本化备份与恢复、数据库升级和失败恢复，不能依赖演示内存状态。
- 应用内真实 GitHub 登录/退出/重连；创建或选择用户自己的独立私有数据仓库；发现远端已有账本、下载、编辑回传、首次上传、多端冲突与删除处理；四种主状态由事实推导。
- 云端账目上传前客户端加密，密钥恢复与凭证隔离；共用账户在仅本地和仅云端账本并存时不泄露数据、不伪造完整余额。

GitHub 登录、私有仓库创建与同步是本轮必要功能，不能用 PAT 输入框、开发者 gh 已登录、假成功按钮或仅本机授权代理代替。先核对官方文档选择 GitHub App/OAuth App、Web/Android 授权方式及必要的最小授权服务，验证私有仓库创建权限和跨域/回调。若需要应用注册或服务部署，完成可自动化的实际配置并提供可部署代码；不能把 client secret 或开发者 token 打入静态网页/APK。

Android 短信读取按已记录条件验证：合法且系统/分发允许时实现授权、范围筛选、勾选与识别；确实受限则保留完整粘贴流程并记录证据。不要以此推迟其他必需功能。暂缓项仅限 DELIVERY_SCOPE.md 已列范围。

本轮授权：可以安装本项目必需的开发依赖和独立 Android/JDK 构建工具、使用 gh 在我的 GitHub 账号下配置 BesLedger 源码仓库、创建独立私有账本数据仓库和必要的私有同步测试仓库、推送经过检查的代码、配置 GitHub Actions/Pages、发布静态 Web 与可安装 APK。每类动作限定在 BesLedger 及本轮创建的资源，不修改无关项目，不引入付费服务。数据仓库可采用 BesLedger-Data，测试仓库采用独立名称；若同名已存在先检查身份、内容和可见性，不覆盖或删除既有数据。私有仓库创建后必须读回确认可见性，才允许上传虚构测试账目。

隐私是硬约束：我的真实账单、工资、银行卡资料、账户余额、短信、XLSX、原始截图与任何密钥不得进入公开仓库、Git 历史、测试/截图/日志、Web 或 APK。演示数据均为虚构。所有集成测试使用独立虚构数据；不要读取私人财务文件来生成公开 fixture，也不要自动导入或上传我的真实账目，即使目标仓库是私有的。gh 凭证只供开发操作，不能作为最终应用配置。签名材料、OAuth secret、恢复密钥保存于受保护且被忽略的位置，提供备份说明，不输出到聊天或日志。

依照仓库规则创建阶段提交并推送可复现代码，提交前运行规定脚本取得实际模型标识署名。先审查暂存文件和产物再推送；不重写已有历史，不用强制推送，不因构建困难改坏其他项目的系统环境。新增或修改文本遵守 CRLF 规则，保留必要中文边界注释。APK 使用明确标注的签名；优先形成可持续升级的专用发布签名，密钥不得公开。若先生成调试 APK，要继续完成发布构建，不能据此宣布正式版本完成。

执行方法：先列阶段与验收清单，随即动手。建立并持续更新 docs/IMPLEMENTATION_STATUS.md，记录已完成、未完成、有效命令、实际环境、下一步和阻塞；上下文压缩或任务恢复后直接继续，不重复从头规划。合理默认值写简短决策记录并落实。每个阶段完成相应测试，失败就定位并修复；不要仅为凑覆盖率写复述实现的测试。

测试必须覆盖整数金额、期初边界、转账双端、借贷利息、关联退款、周期幂等、默认时间、备份恢复、升级、同步冲突及删除恢复。浏览器测试至少验证主要页面、粘贴/保存/编辑、离线重开、子路径部署和手机/iPad/桌面布局。至少用两个独立存储环境与真实私有测试仓库验证登录后的远端发现和双向同步；同时保留断网/响应丢失/权限失效的模拟测试。完成 Android 构建、签名检查及可用模拟器或真机安装运行，真机未接入则明确标为待验证，不能把桌面 Web 测试当作 Android 真机通过。

如果遇到必须由我完成的外部登录、二次验证、应用注册确认、权限授予或设备接入，先继续所有不依赖它的工作，将缺少的动作、原因和已经准备好的配置集中说明。不要把缺少生产配置的 GitHub 登录宣称为已完成，也不要因为一个外部阻塞停止其余编码和验证。

最终交付：源码仓库和提交、Web 可访问 URL及生产构建、APK 文件及 SHA-256/版本/签名说明、实际测试结果与设备矩阵、GitHub 登录/私有仓库/同步验证结果、部署和数据恢复说明、明确的剩余限制。按 DELIVERY_SCOPE.md 逐项验收，所有必需项真实完成才报告完成；不能用“后续可扩展”隐藏本轮遗漏。
