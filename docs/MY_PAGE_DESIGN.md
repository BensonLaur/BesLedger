# 我的与同步设计

更新：2026-10-30。用于本轮按原型调整正式应用；已有视觉基线继续沿用，登录、密钥和同步行为采用本页补充。原型 HTML 已补齐模拟状态，正式应用仍以真实会话和存储结果为准。

登录保持、自动准备私有存储、同步密钥加密保存及本地/云端账本并存已完成实现和相关验证；本轮已同步落实下述分组列表、连接面板、状态摘要、密钥说明及离线/失败提示。验证证据见 [逐项验收](DELIVERY_VERIFICATION.md)，数据规则见 [同步模型](SYNC_MODEL.md)。

## 页面组织

“我的”沿用原型的分组列表、图标、触摸反馈和留白，避免首次打开就展示大段技术文字。常用动作清楚可见；只有影响用户选择的说明留在动作附近。

| 区域 | 常用内容 | 展示要求 |
| --- | --- | --- |
| 页头 | 账本已打开、保存位置、锁定账本 | 说明下次打开需输入解锁密码；锁定不退出 GitHub 或删除数据 |
| 日常记账 | 账户管理、事件与周期账等已有入口 | 保留原型风格；未实现功能不能用演示成功替代 |
| 密码与保护 | 修改解锁密码、查看与保存恢复密钥 | 密钥用途直接对应“忘记密码”；共用首次保存时的复制反馈 |
| 备份与恢复 | 导出账本备份、从备份恢复账本 | 先校验、数量预览、设置并确认新密码，再明确同意替换 |
| 跨设备同步 | 账本管理、GitHub 登录与连接 | 连接摘要显示真实状态；具体上传、下载、冲突和密钥管理放在账本管理 |
| 隐私与帮助 | 回收站、短信处理说明、授权详情、源码与使用说明 | 按需展开，不要求用户理解加密算法或部署配置才能记账 |

“隐私与帮助”之后、版本信息之前保留独立的“支持 Bes记账”入口，默认收起、用户主动打开；普通记账、登录及同步流程不主动展示。手机底部卡片、电脑两列面板的细节见 [自愿支持设计](SUPPORT.md)。

同一 GitHub 连接组件可在“我的”和账本管理复用，必须使用同一真实会话状态，不能各自维护会失步的演示开关。首屏显示简短摘要，安装、授权、权限说明可在展开区域或独立面板呈现。

## 连接状态与动作

| 状态 | 建议显示 | 动作与边界 |
| --- | --- | --- |
| 未连接 | 通过 GitHub · 未登录，本地记账可正常使用 | 提供首次安装说明及“使用 GitHub 登录”；不阻塞本地功能 |
| 首次安装 | 在 GitHub 启用 BesLedger Sync | 说明这是账号中的应用安装，无需另装手机软件；授权前说明实际仓库访问范围 |
| 等待授权 | 等待你在 GitHub 完成授权 | 一次性设备码、打开 GitHub、取消；码失效后重新获取，不能一直假装等待 |
| 已登录、正在准备存储 | 已登录示例用户 · 正在准备私有存储 | 登录与准备存储分开；失败提供重试，不把失败显示为已同步 |
| 已连接且存储就绪 | GitHub · 已登录示例用户 · 登录已保存 | 进入账本管理、退出 GitHub、管理安装；不会仅因登录上传账本 |
| 离线或暂时无法连接 | 已保存登录 · 暂时无法连接，可继续本地记账 | 保留凭证和数据，恢复网络后重试；不把超时、限流或服务故障当成退出 |
| 授权已失效 | GitHub 授权已失效，请重新登录 | 只有确认无法续期或授权被撤销时要求重登；本地账目保留 |
| 仓库不可访问或权限有变化 | 暂时无法访问同步存储，请检查安装范围 | 保留原绑定并提供检查/重试，不偷偷新建空仓库替代 |

正常刷新、切页、重启或锁定解锁后恢复已保存的登录；访问令牌到期优先自动续期。离线时显示“已保存登录”不等于已在线验证。主动退出后不恢复旧登录；清除应用数据、卸载、更换设备或恢复另一空间可能需要重新授权。

默认安装为 All repositories。安装/授权入口附近保留一句明确说明：“授权包含你账号内其他仓库（包括私有仓库）的内容读写权限；应用只用确认过的账本存储。”展开详情说明 Contents 写入、Repository creation 写入、Metadata 只读，以及代码约束不等同 GitHub 平台隔离。不能继续使用旧 OAuth repo 文案或“只能访问专用仓库”的承诺。

## 区分三种身份与三种状态

- 资金账户是现金、银行卡、往来款等；账本用来组织账目；GitHub 账号只提供可选同步存储。登录不创建新的资金账户，也不替换本地账本。
- “已登录”描述 GitHub 连接，“已解锁”描述当前设备能否读取本地数据，“已同步”描述某本账最近一次确认的版本；三者不能共用一个含糊的绿色状态标记。
- 账本仍使用仅本地、仅云端、已同步、待同步四种主状态；网络错误、冲突和最近检查时间作为补充。“已同步”不能承诺此刻其他设备没有新修改。
- 手机本地 A 与云端 B 可并存，各自上传或下载；同名不同 ID 不合并。同一 ID 的副本按同步规则整合，同笔冲突需明确选择。

## 解锁与同步密钥

首次上传自动使用当前本地空间的恢复密钥。另一设备首次下载时才要求原设备的同步恢复密钥，成功解密并校验后按 GitHub 账号、仓库和账本绑定加密保存。日常返回账本管理、刷新、锁定解锁或重启后自动取用，不重复弹出必填框。

| 位置/场景 | 文案与动作 |
| --- | --- |
| 我的 → 查看与保存恢复密钥 | 标明这是当前本地空间的恢复密钥；不能说它一定能解密从别的设备下载的所有账本 |
| 首次下载缺少原设备密钥 | “输入原设备的同步恢复密钥”；验证失败保留已有账本和原先保存的密钥 |
| 已保存某账本密钥 | 简短显示“同步密钥已在此设备加密保存”，同步时无需输入；更换输入应作为可选操作 |
| 账本卡片 → 同步密钥 | 可“忘记此设备密钥”，说明不删除账目或云端数据；之后可能需要重新输入 |
| 提醒独立备份 | 记住密钥只方便当前设备，换设备或恢复备份仍可能需要原设备密钥 |

锁定本地空间与退出 GitHub 必须分开：锁定清除当前内存访问能力，保留受密码保护的凭证和同步密钥；再次解锁后恢复使用。退出 GitHub 清除本机登录凭证，保留本地账目和受本地密码保护的同步密钥，不撤销其他设备的独立登录。忘记同步密钥是另一项明确操作。

同步密钥不进入导出备份、云端账本或登录中转；恢复备份不会恢复这些已记住的外部账本密钥。页面不应宣称硬件 Keystore 保护、密钥绝不可能被读取或退出后取证擦除等未实现保证。技术边界见 [安全与恢复](SECURITY_AND_RECOVERY.md)。

用户忘记密码时，从解锁页进入“忘记密码？”，用这台设备的恢复密钥重设并确认新密码，保留现有账本和账目，不要求备份文件。Web 与 Android 共用此流程；错误密钥、取消和并发变化不会替换本地数据。详情见 [安全与恢复](SECURITY_AND_RECOVERY.md#忘记本机解锁密码)。

## 修改密码与恢复入口的衔接

“我的 → 修改解锁密码”要求原解锁密码、新密码及再次确认，字段使用与解锁页相同的显示/隐藏方式，提交后重新隐藏。验证成功后只更换同一主密钥的密码封装，保留全部账本、账目、设备身份、绑定、已保存登录和同步密钥；恢复密钥不变，先前导出的备份仍使用导出时的密码。

已打开账本时点击“忘记密码？”先说明下一步会锁定，并提供“先查看与保存恢复密钥”；用户选择“前往重设密码”后才锁定并进入共用的重设页。避免误点立即失去当前访问能力；返回或关闭不改密码，不清理账目。

恢复密钥面板直接说明：在打开账本页点击“忘记密码？”，用这份密钥设置新密码，已有账目保留。复制反馈与首次创建共用，复制成功不声称已独立保存。其他设备同步密钥的边界收进“这份密钥适用于哪些账本？”。

“我的”和锁定页使用同一个“从备份恢复账本”名称、错误说明、校验与预览流程。恢复前设置并确认新密码，明确提示备份仅包含导出时已有账目，替换的是当前全部本地账本；更换文件或凭证立即使预览及替换同意失效。

## 首次使用与解锁入口

普通页面和当前帮助统一称“解锁密码”，与 GitHub 登录密码不同。

| 本地状态 | 首屏与主要动作 | 按需展开 |
| --- | --- | --- |
| 尚未创建 | “开始记账”；填写账本名称、解锁密码并再次确认，再“创建账本” | 底部直接提供“从备份恢复账本” |
| 已有账本、当前锁定 | “欢迎回来”；说明保存位置，提示“输入你设置的解锁密码，继续记账”，再“打开账本” | 密码框旁保留“忘记密码？”，底部直接提供“从备份恢复账本” |
| 忘记密码 | “重设解锁密码”；恢复密钥、新密码、确认新密码；强调已有账目保留 | 顶部返回解锁，返回时清空敏感输入并隐藏密码 |

仅设置新密码时提示至少 10 个字符；普通解锁只提示输入已有密码。密码默认隐藏，眼睛按钮可临时显示，提交、返回或切换流程后重新隐藏。减少品牌区和卡片留白，320 像素窄屏也优先呈现主要操作；GitHub 与保存原理放入“账目在本机加密保存”的展开说明，不阻挡记账。

普通解锁页不展示故障修复。只有当前数据确有读取异常，且同一输入密码能够完整验证备用副本时，才出现“查看本地备用副本”；先展示账本、账户和账目数量，说明它是最近一次本地保存之前的内容及近期修改可能不在其中，经明确勾选确认才恢复。普通密码错误、可正常读取的当前账本、不可用备用副本及未来不支持的格式均不能进入此流程。确认时再次验证当前异常及副本，并检查本地修订号；返回或取消不写入数据。

首次创建的两次密码不一致时不创建本地空间。保存恢复密钥页提供“复制恢复密钥”：成功提示粘贴到安全位置并确认保存，失败提示手动选中复制；复制成功不勾选“我已独立保存恢复密钥”，进入账本仍需用户自行确认。

锁定与已解锁页面共用更新提示。有新版本时可“更新并重新打开”；未完成的密码、恢复信息、账本名称、恢复密钥保存或弹窗表单会阻止更新，避免刷新丢失输入。更新只替换应用资源，不清理账本数据库；检查更新不会自动应用更新。

保存位置由实际运行环境决定，不根据屏幕宽度或设备名称猜测：Android 安装版为“此设备”，普通网页（含 iPad Safari）为“此浏览器”，主屏幕 PWA 为“此应用”。原生使用 Capacitor 能力判断，PWA 使用 standalone 显示模式及 iPad 的主屏幕运行标记；主屏幕模拟测试不代表已在真实 iPad 安装验证。展开说明解释当前浏览器/网址或应用的本地空间，更换时使用备份或同步取回账本。

输错密码后保留错误提示、隐藏明文并选中密码框，方便直接重输；输入新内容后清除旧提示。“忘记密码？”说明恢复密钥来自创建本地账本时的独立保存，其他设备新建密钥不能通用；未保存密钥时可转入备份恢复，并说明仅能找回备份已有内容，找不到可用密码、密钥或副本时无法直接解开当前账目。

解锁页备份恢复分两步：先选择文件，用备份原密码或恢复密钥校验，展示账本、账户和账目数量；再设置并确认新密码，已有本地内容时勾选明确替换同意后提交。首次校验、错误文件/凭证、退出和取消均不写入账本；“我的”更换文件或凭证时也清除旧预览与替换同意。确认时重新校验并检查预览时的本地版本，其他窗口修改后须重新校验，防止覆盖新账目。恢复中的返回暂不可用；已进入原子提交时不承诺撤销写入，关闭或锁定后不由迟到回调重新解锁。

此轮先更新共用界面及 Web 预览；Android 构建、软键盘与真机体验留到集中反馈后统一验证，不以浏览器尺寸测试代替真机结果。

## 账本管理与跨设备同步入口

“跨设备同步”集中解释用途及 GitHub 连接；“账本管理”直接选择这里的账本或其他设备已上传的账本。已连接时使用简短账号摘要，仓库名、独立存储选择和技术排查放入展开说明。未连接时分步骤引导首次启用，并为已有授权者提供直接登录。

首次使用增加“从其他设备取回账本”，仅准备有独立解锁密码的本地空间，不生成无用空账。原设备首次上传需确认目标及恢复密钥已保存；另一设备按账本验证密钥、预览名称和数量后确认添加，已有账本继续保留。错误密钥、取消、过期预览和并发变化不采用新密钥或替换账目。

日常同步仍由用户点击；状态分别展示成功同步时间和云端检查时间，离线不暗示所有设备一致。冲突显示业务字段，选择与稍后处理均保存在本地加密空间，确认前不计入余额；全部确认后还需同步。详细协议见 [同步模型](SYNC_MODEL.md)。

## 普通用户的完整流程

1. 本地创建账本并设置解锁密码，独立保存恢复密钥，直接开始记账。
2. 日后需要跨设备时，在“我的”安装并授权 BesLedger Sync。普通用户不用注册 GitHub App、创建仓库、填写名称或部署中转服务。
3. 应用自动准备私有存储并发现账本目录；本地账本保持原样，不自动上传或覆盖。
4. 在账本管理明确选择“首次上传”；另一设备登录后选择云端账本，首次输入原设备密钥并解密下载。
5. 以后正常解锁，修改后点击该账本的“同步”；另一设备也同步取回更新。自动取用密钥不等于后台实时自动上传。

Web/PWA 与 Android 使用同样的用户流程。维护者部署、Cloudflare 账号、服务地址和 App 注册信息不进入普通用户必填项。更换 Web 网址相当于换一个独立客户端，不应建议清除站点数据来完成更新。

## 改版回归检查

- 未连接时可以离线创建账本、账户和记账，不出现强制 GitHub 登录。
- 登录、准备存储和账本同步显示不同状态；已有本地 A、云端 B 时两者并存，登录不上传 A。
- 切页、刷新、锁定解锁、杀进程重启后保持登录；已验证的账本密钥无需重输，且锁定时不能绕过本地解锁访问数据。
- 新设备首次输入正确原设备密钥后可下载；错误输入不会覆盖旧副本；忘记密钥不删账目。
- 断网、超时和权限变化不会清空账本、误显示同步成功或无理由要求重复授权。
- 主动退出只清除本机登录，重启不会复活；不同账本或 GitHub 账号不串用密钥。
- Android 覆盖升级继续使用原签名和递增 versionCode；原账户、流水、绑定和已保存凭证保留。测试只使用虚构数据。
- 320 像素窄屏、软键盘和长账号名称下无横向溢出，按钮有点击反馈，状态不只靠颜色区分。
